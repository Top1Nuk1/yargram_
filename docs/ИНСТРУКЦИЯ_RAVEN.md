# Инструкция: перенос Yargram на Raven Host (бесплатный Apps-хостинг)

Подробная, шаг за шагом. Рассчитана на то, что вы идёте сверху вниз и просто
выполняете команды. Всё, что нужно сделать **на вашем компьютере**, собрано в
части А; всё, что **на Raven Host**, — в части Б.

---

## Что вы получите

Адрес друзей: **`https://yargram.app.ravenhost.space`**

- на нём открывается **лендинг** (описание Yargram);
- сам мессенджер — по **`https://yargram.app.ravenhost.space/app`**.

Часть `app` в адресе — это поддомен, который Raven даёт всем приложениям по
схеме `имя.app.ravenhost.space`. Убрать её нельзя, это их именование.

| Возможность | Будет работать? |
| --- | --- |
| Регистрация, вход, коды на почту | да |
| Переписка, файлы до 100 МБ, голосовые | да |
| Фоны, баннеры, аватары | да |
| Присутствие («онлайн» / «печатает») | да |
| Поиск, «Активные сеансы» | да |
| **Звонки и видеозвонки** | **да** — внутри Radmin-VPN работают по STUN; для интернета добавляется TURN-релей (Open Relay/Metered), настройка в `.env` |
| **PostgreSQL** | **попробовать** — у Raven, похоже, есть managed PostgreSQL, но гарантии нет; JSON-хранилище надёжнее и проще |
| HTTPS | да, панель выдаёт сама |
| Свой домен | нельзя на этом тарифе |

**Звонки работают.** Внутри Radmin-VPN и одной локальной сети они идут по
публичному STUN и не требуют настройки. Для звонков «наружу» (разные сети,
симметричный NAT) добавляется внешний TURN-релей — его настройка описана в
части **Б7½** ниже. Единственный оставшийся серьёзный компромисс — **PostgreSQL**:
его на Raven можно попробовать, но JSON-хранилище надёжнее и проще для 3–7 друзей.

JSON-хранилище пишет атомарно (временный файл → `rename`) и сериализует записи
через очередь — для 3–7 друзей этого хватит с запасом. Чего на нём не будет:
миграций и индексов PostgreSQL. Это станет заметно, когда появятся каналы и
поиск по большой истории.

---

## Кратко: 9 действий

1. 🔥 **Создать приватный репозиторий на GitHub и запушить код** — у проекта нет
   `git remote`, на сервер нечего клонировать.
2. 🔥 **Сохранить `DB_ENCRYPTION_KEY`** с компьютера — придумать новый нельзя.
3. **Снять свежую копию** — `Сделать копию Yargram.bat`.
4. **Зарегистрироваться** на Raven, создать приложение (Node.js 22, поддомен
   `yargram`, Free).
5. **Спросить в их Discord** про PostgreSQL и UDP.
6. **Добавить SSH-ключ**, клонировать код в веб-консоли, **собрать его там же**
   (`npm install` → `npm run build` → `npm prune --omit=dev`).
7. **Заполнить переменные среды** — `DB_ENCRYPTION_KEY` и `MAIL_*` копируются
   с вашего ПК.
8. **Загрузить копию и импортировать.**
9. **Включить ежедневные копии** и раз в неделю скачивать их к себе.

Дальше — то же самое, но развёрнуто.

# Часть А. На своём компьютере (Windows)

Открывайте **PowerShell** (Пуск → наберите `PowerShell` → Enter). Все команды
части А выполняются там.

## А1. Свежая копия данных

Двойной щелчок по файлу **`Сделать копию Yargram.bat`** в папке проекта. Появится
окно с отчётом; когда оно закроется или перестанет меняться — копия готова.

Копия лежит в `C:\Games\YarGram\runtime\backups\<ДАТА>_<ВРЕМЯ>\`, например
`2026-10-03_0147`. Откройте эту папку в проводнике — она понадобится в части В.

> Если лень искать: `npm run backup:status` покажет список копий и самую свежую.

## А2. 🔥 Сохранить ключ шифрования

Откройте блокнотом файл `КЛЮЧ.txt` из папки копии (А1) — там одна строка.
Скопируйте её в надёжное место (менеджер паролей или просто в отдельный файл
на флешке).

**Почему это критично.** Тексты сообщений и файлы лежат в базе зашифрованными
этим ключом (AES-256-GCM). Импорт переносит их как есть, не перешифровывая.
Если на сервере задать другой ключ — база примет данные **без ошибки**, но ни
одно сообщение не прочитается.

- 🔥 `DB_ENCRYPTION_KEY` — **перенести тот же самый**, до последнего символа.
- `JWT_SECRET` — наоборот, можно придумать новый (только сессии обнулятся,
  друзья перезайдут).

## А3. SSH-ключ

Нужен, чтобы сервер мог забрать код из вашего репозитория.

```powershell
ssh-keygen -t ed25519 -C "yargram"
```

Три раза нажмите `Enter` (не задавайте парольную фразу). Затем выведите ключ:

```powershell
type $HOME\.ssh\id_ed25519.pub
```

Получите строку вида `ssh-ed25519 AAAAC3Nza… yargram`. **Скопируйте её в
блокнот** — понадобится в шагах А4 и Б4.

## А4. Создать приватный репозиторий и запушить код

Здесь два шага: сначала закоммитить, потом отправить.

### А4.1. Закоммитить

```powershell
cd C:\Games\YarGram
git status --short
```

Вывод покажет список изменённых файлов. Это нормально — изменений накопилось
много (167), последний коммит был 27 сентября.

```powershell
git add -A
git commit -m "Подготовка к переезду на Raven Host"
```

Проверьте, что `.env` **не попал** в коммит (там пароли почты и ключ):

```powershell
git status --short | Select-String "\.env$"
```

Должно быть пусто. `.env` и `runtime/` в `.gitignore`, так и задумано.

### А4.2. Создать репозиторий на GitHub

1. Откройте `github.com` и войдите (или зарегистрируйтесь).
2. Справа сверху **`+`** → **New repository**.
3. Заполните:
   - **Repository name**: `yargram`
   - 🔥 **Private** (обязательно — там ваш код)
   - Ничего больше не отмечайте (галочки README, .gitignore — **не нужны**)
4. Нажмите **Create repository**.

GitHub покажет страницу с командами. Нужна секция
**«…or push an existing repository from the command line»**. Выполните свои
аналоги этих команд (подставьте свой логин):

```powershell
cd C:\Games\YarGram
git remote add origin git@github.com:<ВАШ_ЛОГИН>/yargram.git
git branch -M main
git push -u origin main
```

Если `git push` спросит про аутентификацию — войдите в браузере. Если ругается
на ключ — добавьте ключ из А3 на GitHub: **Settings → SSH and GPG keys →
New SSH key**.

Проверка: обновите страницу репозитория — файлы должны появиться.

# Часть Б. На Raven Host

## Б1. Регистрация

1. Откройте `ravenhost.space` → кнопка **Register** (или
   `ravenhost.space/register`).
2. Заполните e-mail, имя пользователя, пароль. **Карта не нужна.**
3. Подтвердите e-mail, если попросят.

## Б2. Создать приложение

В панели: **Create server** (или «New server»).

Категория: **Apps, bots & scripts** (не Minecraft!).

| Поле | Что выбрать |
| --- | --- |
| Name | `yargram` |
| Subdomain / Address | `yargram` → получится `yargram.app.ravenhost.space` |
| Plan | **Free** |
| Runtime / Egg | **Node.js** (версия 22 или ближайшая доступная) |

Дождитесь, пока статус станет **Running** (обычно меньше минуты).

## Б3. Узнать порт

В панели найдите раздел **Settings → Allocations** (или «Network»). Там будет
адрес вида `yargram.app.ravenhost.space:XXXXX` или просто номер порта,
например `25565`.

**Запишите этот номер порта.** Он понадобится в шаге Б7 как значение `PORT`.

> Если панель не показывает порт явно — посмотрите в разделе **Console** вывод
> переменных или спросите в их Discord. Yargram слушает тот порт, что задан в
> `PORT`, и он должен совпасть с тем, что пробросила панель.

## Б4. Добавить SSH-ключ в панель

В панели: **Settings → SSH Keys → Add Key** (или «Add SSH Key»).

Вставьте строку из шага А3 (`ssh-ed25519 AAAAC3Nza… yargram`) и сохраните.

## Б5. Клонировать код

В панели откройте **Console** — это веб-терминал, аналог SSH. Все команды
части Б выполняются там.

```bash
git clone git@github.com:<ВАШ_ЛОГИН>/yargram.git ~/yargram
```

Если спросит `Are you sure you want to continue connecting (yes/no)?` —
наберите `yes` и `Enter`.

```bash
cd ~/yargram
ls
```

Должны быть папки `apps`, `scripts`, `docs`, файл `package.json`.

> **Если git не работает в их консоли** — запасной путь: соберите архив.
>
> 1. На Windows сначала соберите проект: `cd C:\Games\YarGram && npm run build`.
> 2. Упакуйте `C:\Games\YarGram` в ZIP (7-Zip → «Добавить в архив»), **исключив**
>    `node_modules` и `runtime`, но **обязательно оставив** `dist` (папки
>    `apps\web\dist`, `apps\landing\dist`, `apps\server\dist`) — они в
>    `.gitignore`, поэтому через git не переносятся.
> 3. В панели **File Manager → Upload** загрузите архив и распакуйте
>    («Extract») в `~/yargram`.
> 4. В **Console** доведите зависимости — сборка уже готова, поэтому нужны
>    только runtime-пакеты:
>
>    ```bash
>    cd ~/yargram && npm install --workspaces --include-workspace-root --omit=dev
>    ```
>
>    Шаг Б6 в этом случае пропускаете.

## Б6. Установка и сборка

🔥 **`dist/` в `.gitignore`** — то есть собранные файлы через git **не уедут**.
Значит собирать нужно прямо на сервере, и для этого нужны dev-зависимости:

```bash
cd ~/yargram
npm install --workspaces --include-workspace-root
npm run build
npm prune --omit=dev
```

Разбор трёх команд:

1. `npm install … --include-workspace-root` — ставит **все** зависимости,
   включая dev. Без них собрать нельзя: `npm run build` запускает `tsc` и
   `vite`, а это dev-пакеты.
2. `npm run build` — собирает лендинг, веб и сервер. Занимает около минуты.
3. `npm prune --omit=dev` — удаляет dev-пакеты обратно: после сборки они не
   нужны, а на Free-тарифе всего 10 ГБ диска.

Проверьте, что сборка удалась:

```bash
ls apps/web/dist apps/landing/dist apps/server/dist
```

Все три папки должны существовать и быть непустыми. Если `ls` ругается
«No such file or directory» — сборка не прошла, смотрите вывод `npm run build`.

> ⚠️ **Если сборка падает с «out of memory»** (на Free-тарифе 1.5 ГБ RAM):
> соберите на компьютере и загрузите готовые папки вручную.
> На Windows: `cd C:\Games\YarGram && npm run build`.
> Затем в панели **File Manager → Upload** загрузите содержимое
> `apps\web\dist`, `apps\landing\dist` и `apps\server\dist` в соответствующие
> папки на сервере — именно поэтому `dist` в `.gitignore`, через git они не
> переносятся.

## Б7. Файл `.env` на сервере

Самый надёжный путь — **перенести ваш `.env` с компьютера**, а не заполнять
с нуля: тогда ключ шифрования и почта совпадут гарантированно.

```bash
cd ~/yargram
nano .env
```

Откроется редактор. Вставьте содержимое (правый щелчок обычно вставляет),
затем измените три строки и добавьте, чего не хватает:

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=<ПОРТ_ИЗ_Б3>
DATABASE_DRIVER=postgres   # попробуйте postgres; если Raven его не даёт — поставьте json
PUBLIC_ORIGIN=https://yargram.app.ravenhost.space
TRUST_PROXY=loopback
```

Остальные строки (`JWT_SECRET`, `DB_ENCRYPTION_KEY`, `MAIL_*`) **скопируйте из
вашего `.env` на компьютере без изменений**.

Сохранить: `Ctrl+O`, `Enter`. Выйти: `Ctrl+X`.

Затем закройте файл от чужих глаз:

```bash
chmod 600 ~/yargram/.env
```

### Если `.env` переносить не хотите — заполните вручную

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` |
| `HOST` | `0.0.0.0` |
| `PORT` | порт из шага Б3 |
| `DATABASE_DRIVER` | `postgres` (попробуйте; если Raven не даёт — `json`) |
| `PUBLIC_ORIGIN` | `https://yargram.app.ravenhost.space` |
| `TRUST_PROXY` | `loopback` — иначе в «Сеансах» будет `http://`, а не `https://` |
| `JWT_SECRET` | новая случайная строка 32+ символов |
| `DB_ENCRYPTION_KEY` | 🔥 **тот же, что на ПК** (из `КЛЮЧ.txt`, шаг А2) |
| `MAIL_DRIVER` | `smtp` |
| `MAIL_HOST` | `smtp.gmail.com` |
| `MAIL_PORT` | `587` |
| `MAIL_USER` | ваш ящик (как у вас на ПК) |
| `MAIL_PASS` | пароль приложения (как у вас на ПК) |
| `MAIL_FROM` | тот же ящик |

`JWT_SECRET` сгенерировать можно так (на сервере или на ПК):

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Б7½. Звонки: TURN-релей (опционально)

Звонки идут по WebRTC. Внутри одной сети и через Radmin-VPN хватает публичного
STUN — ничего настраивать не надо. Но если собеседники в разных сетях с
симметричным NAT (частый случай — мобильный интернет), прямого соединения не
будет без TURN-релея, который перегоняет медиапоток через себя.

Свой `coturn` на shared-хостинге поднять нельзя (нужен root и открытый UDP).
Поэтому Yargram берёт **временные** реквизиты у внешнего сервиса (Open Relay,
Metered и подобные) — сервер запрашивает их перед звонком, ключ сервиса остаётся
на сервере и не светится в браузере.

Настройка в `.env`:

```dotenv
TURN_CREDENTIALS_URL=https://api.metered.live/v1/<ВАШ_КЛЮЧ>/credentials
TURN_CREDENTIALS_TTL_SECONDS=600
```

`TURN_CREDENTIALS_URL` должен отдавать JSON вида
`{"iceServers":[{"urls":"turn:…","username":"…","credential":"…"}]}` (или просто
массив `iceServers`). Логин и пароль живут минуты, поэтому сервер кэширует их на
`TURN_CREDENTIALS_TTL_SECONDS` (30–86400, по умолчанию 600) и раздаёт один набор
всем участникам звонка.

Без `TURN_CREDENTIALS_URL` звонки всё равно работают — но только там, где
достаточно STUN (одна локальная сеть, Radmin-VPN). Для звонков «наружу» релей нужен.

## Б8. Переменные в панели

Некоторые панели подменяют `.env` своими переменными. Зайдите
**Settings → Environment Variables** и продублируйте туда те же значения,
что в `.env` (как минимум `PORT`, `DATABASE_DRIVER`, `PUBLIC_ORIGIN`,
`TRUST_PROXY`, `NODE_ENV`).

> Если панель не даёт задать переменные — не страшно, `.env` достаточно.

## Б9. Запуск

В панели: **Settings → Start command** (или «Startup command»):

```
cd ~/yargram && node apps/server/dist/index.js
```

Нажмите **Restart** (или «Start»). Журнал — в **Console**:

```bash
tail -50 ~/yargram/runtime/yargram.log
```

В норме там строки вида:

```
Yargram storage: json
Server listening on 0.0.0.0:<ПОРТ>
```

Откройте в браузере `https://yargram.app.ravenhost.space` — должен открыться
лендинг. А `https://yargram.app.ravenhost.space/app` — сам мессенджер.

# Часть В. Перенос данных

## В1. Загрузить базу

Из папки копии (шаг А1) возьмите файл `database.json`.

В панели: **File Manager** → зайдите в `~/yargram` → **Upload** → выберите
`database.json`. Файл окажется по пути `~/yargram/database.json`.

## В2. Загрузить вложения

Из `C:\Games\YarGram\runtime\backups\uploads\` возьмите **всё содержимое**
(это фотографии и файлы из переписки).

В панели: **File Manager** → создайте папку
`~/yargram/apps/server/data/uploads` → **Upload** → загрузите файлы внутрь.

## В3. Импорт

В **Console**:

```bash
cd ~/yargram
npm run db:import -- ~/yargram/database.json
```

Скрипт напечатает, сколько чего перенесено:

```
Import complete: 12 users, 8 conversations, 431 messages, …
```

🔥 Затем **обязательно** сверьте ключ:

```bash
grep DB_ENCRYPTION_KEY ~/yargram/.env
```

Строка должна совпасть с `КЛЮЧ.txt` из шага А2. Если нет — переписка
переехала, но не прочитается; исправьте `.env` и перезапустите.

⚠️ Повторный импорт в непустую базу отклоняется — это защита, а не ошибка.

# Часть Е. Обновление кода в будущем

Когда появляется новая версия:

1. На компьютере: `git add -A && git commit -m "..." && git push`.
2. В **Console** на сервере:

```bash
cd ~/yargram && git pull
npm install --workspaces --include-workspace-root

npm prune --omit=dev
```

🔥 `npm run build` здесь обязателен: `dist/` в `.gitignore`, поэтому новая
сборка с компьютера сама не приедет — её нужно сделать на сервере.

| Сайт не открывается | правильный ли адрес; в Console: `curl -s localhost:<ПОРТ>/api/health` должен ответить `{"status":"ok",…}` |
| Лендинг открывается, `/app` — 404 | не попали `dist`-папки (шаг А5) |
| В «Сеансах» `http://` вместо `https://` | `TRUST_PROXY=loopback` задан и контейнер перезапущен |
| Сообщения переехали, но «пустые» | `DB_ENCRYPTION_KEY` не совпадает с тем, что был на ПК |
| Импорт отказался | база непустая — это защита, не ошибка |
| Сервер не стартует | журнал: `tail -100 ~/yargram/runtime/yargram.log` |
| `EADDRINUSE` | порт в `PORT` не совпадает с тем, что выделила панель (шаг Б3) |
| `permission denied` | файлы чужие: `chown -R $(whoami) ~/yargram` |
| Письмо с кодом не приходит | почта — единая точка отказа; проверьте `MAIL_*`, что они те же, что на ПК |

Журнал всегда здесь:

```bash
tail -100 ~/yargram/runtime/yargram.log
```

## Чего здесь не будет

- **Гарантии звонков «в любую точку интернета».** Внутри Radmin-VPN и одной сети
  звонки идут по STUN без настройки; для остального нужен TURN-релей (см. Б7½).
  Если не хотите настраивать релей — VPS Starter за $3.99/мес даёт свои UDP-порты
  и `coturn` (инструкция `docs/ИНСТРУКЦИЯ.md`).
- **Своего домена.** `app.ravenhost.space` — wildcard самого Raven, привязать
  свой домен на shared-тарифе нельзя. На VPS — можно.
- **Push-уведомлений** в фоне — их пока нет в Yargram вообще.
