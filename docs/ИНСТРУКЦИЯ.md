# Инструкция: перенос Yargram на сервер (Oracle Cloud, бесплатно)

Что делаем. Сейчас Yargram живёт на вашем компьютере: сервер и база
поднимаются файлом `Запустить Yargram.bat`, друзья заходят по адресу Radmin VPN.
После переезда Yargram работает круглосуточно на арендованном сервере,
**ваш компьютер может быть выключен**, а друзья заходят по обычной ссылке в
браузере — без VPN, из любой сети, со звонками.

Рассчитано на один вечер. Команды копируются как есть; вместо `<IP>`,
`<ЛОГИН>` и `<ДОМЕН>` подставляйте свои значения.

---

## Сначала — два решения

**1. Будет ли домен?** Это единственное, что влияет на постоянство адреса.

| | С доменом | Без домена |
| --- | --- | --- |
| Адрес | постоянный, красивый (`yargram.example.com`) | `https://что-то.trycloudflare.com`, **меняется при каждом запуске** |
| HTTPS | настоящий, через Let's Encrypt | через Cloudflare Tunnel |
| Что нужно | купить домен (~300 ₽/год) и направить его на сервер | ничего |
| Файлы | лимит по диску | лимит 100 МБ (совпадает с пределом Yargram, «на грани») |

Домен стоит копейки и снимает сразу три проблемы — **берите домен**, если
возможность есть. В инструкции оба пути: шаг 14А (домен) и 14Б (без домена).

**2. Как код попадёт на сервер?** Рекомендую приватный репозиторий на GitHub:
это заодно вторая копия кода **вне** Oracle (инстанс могут забрать — см.
«Что важно знать» ниже), и обновления потом делаются одной командой `git pull`.
Альтернатива без GitHub — переслать архив (шаг 8, вариант Б).

---

## Что важно знать до начала

- 🔥 **Простаивающий инстанс Oracle может забрать.** Если за 7 дней CPU, сеть и
  память всё время ниже 20 % — инстанс считают простаивающим. Мессенджер на
  3–7 человек под это описание подходит идеально. Поэтому **копии обязаны
  уезжать с сервера** (шаг 16) — это не формальность, а главная защита.
- 🔥 **Ключ шифрования нужно перенести, а не придумать заново.** Подробно в
  шаге 0.2. Если пропустить — переписка переедет, но не прочитается.
- 🔥 **Порты на Oracle открываются в двух местах**: в облаке (шаг 3) и внутри
  самой машины (шаг 5). Открыть только одно — самая частая ошибка, и выглядит
  она одинаково: «сервер не отвечает».
- **«Out of host capacity» при создании инстанса** — не ваша ошибка. Бесплатные
  ARM-машины выдают из общего пула; помогает другая зона доступности или
  повторная попытка позже.
- ⚠️ Названия кнопок в консоли Oracle со временем меняются. Если пункт
  называется чуть иначе — ищите по смыслу; смысл у шагов не меняется.

# Часть 0. На своём компьютере (Windows)

## Шаг 0.1. Свежая копия данных

Двойной щелчок по **`Сделать копию Yargram.bat`** (или `npm run backup`).
Копия появится в `runtime\backups\<ДАТА>_<ВРЕМЯ>\` — там `database.json`,
`КЛЮЧ.txt` и `README.txt`. Вложения — в `runtime\backups\uploads\`.

Откройте эту папку и **запомните её имя** — например `2026-10-03_0147`.

## Шаг 0.2. 🔥 Сохранить ключ шифрования

Откройте `runtime\backups\<ВАША_ПАПКА>\КЛЮЧ.txt` и скопируйте строку.

**Почему это критично.** Тексты сообщений и файлы лежат в базе зашифрованными
(AES-256-GCM) ключом `DB_ENCRYPTION_KEY` из вашего `.env`. Импорт переносит их
**как есть**, не перешифровывая. Если на сервере задать другой ключ — база
примет данные без ошибки, но ни одно сообщение не прочитается.

- 🔥 `DB_ENCRYPTION_KEY` — **перенести тот же самый**, до последнего символа.
- `JWT_SECRET` — наоборот, можно придумать новый: он только для сессий, все
  просто зайдут в аккаунты заново.

## Шаг 0.3. Отправить код в приватный репозиторий

Сейчас в проекте ~167 незакоммиченных изменений (последний коммит 27.09.2026).
🔥 **Пока вы их не закоммитите, на сервер уедет старый код.**

```powershell
cd C:\Games\YarGram
git status --short          # посмотреть, что изменилось
git add -A
git commit -m "Подготовка к переезду на сервер"
```

Проверьте, что секреты **не** в коммите:

```powershell
git status --short | Select-String "\.env$"
# пусто — значит .env не отслеживается. Так и надо (.env в .gitignore).
```

Заведите репозиторий: github.com → **New repository** → имя `yargram` →
обязательно **Private** → создавать без README. Затем:

```powershell
git remote add origin git@github.com:<ЛОГИН>/yargram.git
git branch -M main
git push -u origin main
```

# Часть 1. Регистрация Oracle Cloud

1. Зайдите на `cloud.oracle.com` → **Sign up** / «Create a free account».
2. Потребуется e-mail, телефон и **банковская карта** — это проверка личности.
   Денег не списывают; возможна временная блокировка ~1 $ (проверка карты),
   которая сама отпускается.
3. **Home region выбирается один раз и больше не меняется.** Берите ближайший к
   вам и к друзьям (Германия/Франкфурт, Нидерланды/Амстердам). От региона
   напрямую зависит качество звонков.
4. Сразу после регистрации: меню → **Billing & Cost Management** → **Budgets** →
   создайте бюджет 1 $ с оповещением на 80 %. ⚠️ Проверка идёт раз в сутки, то
   есть это не блокировка списаний, а раннее предупреждение.

# Часть 2. Создать инстанс

**Compute → Instances → Create instance.**

| Поле | Что выбрать |
| --- | --- |
| Name | `yargram` |
| Image | **Canonical Ubuntu 22.04** (или 24.04) — ⚠️ именно Canonical Ubuntu, не Oracle Linux |
| Shape | **Change shape** → **Ampere (ARM)** → `VM.Standard.A1.Flex` → 2 OCPU / 12 ГБ |
| Networking | оставить предлагаемую VCN по умолчанию; публичный IPv4 — **включить** |
| SSH-ключ | вставить строку из шага 0.4 |
| Boot volume | оставить по умолчанию (47 ГБ) |

Если создание падает с **«Out of host capacity»** — попробуйте другую зону
доступности (AD-1, AD-2, AD-3) либо повторите позже. Это не ошибка в настройках.

**🔥 Зарезервируйте публичный IP.** По умолчанию он эфемерный — при остановке
инстанса адрес сменится, и сломаются `PUBLIC_ORIGIN`, сертификат и ссылка у
друзей. Зайдите: **Networking → Public IPs → Reserve public IP address**,
создайте адрес и **присвойте его инстансу** (присвоение освободит прежний
эфемерный).

Запишите: публичный IP и имя пользователя — **`ubuntu`**.

| --- | --- |

# Часть 5. 🔥 Открыть порты внутри машины

Образы Ubuntu у Oracle идут со своим `iptables`, который пропускает **только
SSH**. `ufw` его не перебивает — правила добавляем прямо в `iptables`,
**перед** закрывающим правилом `REJECT`:

```bash
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 3478 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p udp --dport 3478 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p udp --dport 49160:49200 -j ACCEPT

sudo apt install -y iptables-persistent    # на вопросы — Yes
sudo netfilter-persistent save             # иначе правила исчезнут после перезагрузки
```

Проверка — правила должны быть **выше** строки `REJECT`:

```bash
sudo iptables -L INPUT -n --line-numbers | head -12
```

# Часть 8. Код на сервер

### Вариант А. Через GitHub (рекомендую)

На сервере (вы уже под `yargram`) создайте ключ и покажите его:

```bash
ssh-keygen -t ed25519 -C "yargram-server"    # три раза Enter
cat ~/.ssh/id_ed25519.pub
```

Скопируйте вывод и добавьте на GitHub: репозиторий `yargram` → **Settings →
Deploy keys → Add deploy key** → вставьте, **Allow write access не отмечать**.

```bash
git clone git@github.com:<ЛОГИН>/yargram.git ~/yargram
cd ~/yargram
```

### Вариант Б. Архивом (если без GitHub)

На Windows упакуйте папку проекта в ZIP (например через 7-Zip или WinSCP),
**исключив** `node_modules`, `runtime` и `dist` — они всё равно пересоздадутся
на сервере. Затем:

```powershell
scp C:\путь\к\yargram-src.zip ubuntu@<IP>:/home/ubuntu/
```

На сервере:

```bash
sudo apt install -y unzip
cd /home/ubuntu && unzip yargram-src.zip -d yargram-src
sudo mv yargram-src /home/yargram/yargram
sudo chown -R yargram:yargram /home/yargram/yargram
sudo su - yargram && cd ~/yargram
```

# Часть 11. Перенести данные

С вашего компьютера (новое окно PowerShell, **не** закрывая сеанс SSH):

```powershell
# путь к вашей копии из шага 0.1
scp "C:\Games\YarGram\runtime\backups\2026-10-03_0147\database.json" ubuntu@<IP>:/home/ubuntu/database.json
scp -r "C:\Games\YarGram\runtime\backups\uploads" ubuntu@<IP>:/home/ubuntu/uploads
```

На сервере (от `ubuntu`) разложите по местам и отдайте пользователю `yargram`:

```bash
sudo mkdir -p /home/yargram/yargram/apps/server/data/uploads
sudo cp -r /home/ubuntu/uploads/. /home/yargram/yargram/apps/server/data/uploads/
sudo cp /home/ubuntu/database.json /home/yargram/yargram/database.json
sudo chown -R yargram:yargram /home/yargram/yargram
```

Теперь — импорт (уже под `yargram`):

```bash
sudo su - yargram
cd ~/yargram
npm run db:import -- ~/yargram/database.json
```

Напечатает, сколько чего перенесено: `Import complete: N users, N conversations,
N messages…`.

⚠️ Повторный импорт в уже заполненную базу отклоняется — это защита от
затирания, а не ошибка.

# Часть 12. Настройки (`.env`)

**Самый надёжный способ — перенести ваш `.env` с компьютера**, а не заполнять с
нуля: тогда ключ шифрования и почтовые настройки совпадут гарантированно.

На Windows:

```powershell
scp C:\Games\YarGram\.env ubuntu@<IP>:/home/ubuntu/env-from-pc
```

На сервере:

```bash
sudo cp /home/ubuntu/env-from-pc /home/yargram/yargram/.env
sudo chown yargram:yargram /home/yargram/yargram/.env
sudo chmod 600 /home/yargram/yargram/.env
sudo su - yargram
cd ~/yargram && nano .env
```

Поправьте в нём три строки:

```dotenv
NODE_ENV=production
PUBLIC_ORIGIN=https://<ДОМЕН>          # или адрес туннеля — см. шаг 14
TRUST_PROXY=loopback                   # чтобы в «Сеансах» был https://, а не http://
```

И **проверьте**, что `DB_ENCRYPTION_KEY` — тот же, что в `КЛЮЧ.txt` из шага 0.2:

```bash
grep DB_ENCRYPTION_KEY .env
```

Остальные строки (`JWT_SECRET`, `MAIL_*`) оставьте как есть: почта должна
работать так же, как у вас сейчас.

# Часть 13. Запуск под systemd

```bash
sudo nano /etc/systemd/system/yargram.service
```

Вставьте:

```ini
[Unit]
Description=Yargram server
After=network.target

[Service]
Type=simple
User=yargram
WorkingDirectory=/home/yargram/yargram
# Своя PostgreSQL поднимается этим же скриптом перед стартом сервера.
ExecStartPre=/usr/bin/node scripts/ensure-postgres.mjs
ExecStart=/usr/bin/node apps/server/dist/index.js
Restart=always
RestartSec=5
StandardOutput=append:/home/yargram/yargram/runtime/yargram.log
StandardError=append:/home/yargram/yargram/runtime/yargram.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now yargram
sudo systemctl status yargram
curl -s localhost:3000/api/health        # {"status":"ok",...}
```

Журнал, если что-то не так:

```bash
tail -50 /home/yargram/yargram/runtime/yargram.log
```

# Часть 14. HTTPS

## 14А. С доменом (nginx + Let's Encrypt)

Сначала у регистратора направьте **A-запись** `<ДОМЕН>` на публичный IP
сервера. Подождите, пока запись увидится: `nslookup <ДОМЕН>`.

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo certbot --nginx -d <ДОМЕН>
```

Затем замените `/etc/nginx/sites-available/yargram`:

```nginx
server {
    listen 443 ssl http2;
    server_name <ДОМЕН>;

    ssl_certificate     /etc/letsencrypt/live/<ДОМЕН>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<ДОМЕН>/privkey.pem;

    # WebSocket нужен Socket.IO: сообщения, «печатает», присутствие.
    location /socket.io/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;
    }

    # Лимит тела запроса должен совпасть с лимитом вложения Yargram (100 МиБ).
    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
sudo ln -sf /etc/nginx/sites-available/yargram /etc/nginx/sites-enabled/yargram
sudo nginx -t && sudo systemctl reload nginx
```

## 14Б. Без домена (Cloudflare Tunnel)

🔥 Oracle-инстанс на ARM, поэтому **нужен `arm64`-вариант** `cloudflared`
(обычный `amd64` на ARM не запустится):

```bash
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64 -o cloudflared
sudo install cloudflared /usr/local/bin/cloudflared
cloudflared tunnel --url http://127.0.0.1:3000
```

Он напечатает адрес вида `https://что-то.trycloudflare.com`. Запишите его,
впишите в `.env` как `PUBLIC_ORIGIN=…` и перезапустите:

```bash
sudo systemctl restart yargram
```

⚠️ Три ограничения: адрес **меняется при каждом запуске** (друзьям придётся
присылать ссылку заново); **UDP через туннель не идёт** (звонки выводим через
TURN, шаг 15); тело запроса ≤ 100 МБ.

# Часть 15. Звонки: TURN (обязательно)

Без TURN часть собеседников не соединится никогда: если NAT «симметричный»
(мобильный интернет, часть корпоративных сетей), нужен релей, который
перегоняет медиапоток через себя. Сейчас эту роль играет Radmin VPN — после
переезда её заменяет `coturn`.

```bash
sudo apt install -y coturn
sudo sed -i 's/^#TURNSERVER_ENABLED=1/TURNSERVER_ENABLED=1/' /etc/default/coturn
```

`/etc/turnserver.conf`:

```ini
listening-port=3478
fingerprint
lt-cred-mech
realm=<ДОМЕН_ИЛИ_IP>
user=yargram:<ПАРОЛЬ_ПОСЛОЖНЕЕ>
min-port=49160
max-port=49200
external-ip=<ПУБЛИЧНЫЙ_IP>
no-multicast-peers
```

```bash
sudo systemctl enable --now coturn
```

Затем **пересоберите веб-часть** с адресом релея — это не настройка сервера, а
значение, вшитое в собранный фронтенд:

```bash
sudo su - yargram
cd ~/yargram
export VITE_TURN_URL="turn:<ПУБЛИЧНЫЙ_IP>:3478"
export VITE_TURN_USERNAME="yargram"
export VITE_TURN_CREDENTIAL="<ПАРОЛЬ_ПОСЛОЖНЕЕ>"
npm run build --workspace @yargram/web
exit
sudo systemctl restart yargram
```

# Часть 17. Проверка

| Что | Ожидание |
| --- | --- |
| `curl -s https://<АДРЕС>/api/health` | `{"status":"ok",…}` |

# Если что-то не работает

| Симптом | Первое, что проверить |
| --- | --- |
| Сайт не открывается, «соединение не устанавливается» | порты: шаг 3 (облако) **и** шаг 5 (`iptables`). Обе причины выглядят одинаково |
| Сайт открывается, но нет связи (сообщения не уходят) | WebSocket: блок `location /socket.io/` в nginx (шаг 14А) |
| Сообщения перенеслись, но читаются как «зашифрованное» | `DB_ENCRYPTION_KEY` не совпадает с тем, что был на компьютере (шаг 0.2) |
| Сервер не стартует, в журнале про базу | шаг 10 пропущен: `node scripts/local-postgres.mjs` |
| В «Сеансах» `http://` вместо `https://` | `TRUST_PROXY=loopback` в `.env` (шаг 12) |
| Звонок не соединяется | `coturn` запущен и порты 3478 / 49160–49200 открыты; веб пересобран с `VITE_TURN_*` |
| Письмо с кодом не приходит | почта — единая точка отказа. Проверьте `MAIL_*`, второй ящик подхватывает автоматически |
| Файл на 100 МБ не проходит | лимит Cloudflare Tunnel; переход на nginx снимает |

Журнал всегда здесь:

```bash
tail -100 /home/yargram/yargram/runtime/yargram.log
```

## Что остаётся ограничением

- **Приложение станет публичным** — его увидит любой, кто знает адрес.
- **Почта — единая точка отказа входа**: без письма с кодом войти нельзя.
- **Web Push нет**: уведомления видны только при открытой вкладке.
- **Один процесс**: presence и звонки живут в памяти, две копии сервера на одной
  базе запускать нельзя.
