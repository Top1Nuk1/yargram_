# Yargram 0.1 — мессенджер через Radmin VPN

Версия остаётся 0.1. Добавлено хранение в PostgreSQL, исправлены сборка, профиль, заметки, жалобы и подключение звонков. Инструкция подключения и переноса данных: [docs/DATABASE.md](docs/DATABASE.md). Планы сайта, приложений, Telegram-входа, тем и личного чата: [docs/ROADMAP.md](docs/ROADMAP.md).

Для локальной PostgreSQL перед запуском Yargram откройте отдельный терминал и выполните `npm.cmd run db:local`. Первый перенос JSON при остановленном сервере: `npm.cmd run db:use-local`. Повторять импорт при каждом запуске не нужно.

Yargram запускается на Windows без Docker и временно доступен участникам одной сети Radmin VPN.

- основной адрес с сообщениями и звонками: <https://26.236.251.44:3443>;
- резервный HTTP-адрес без доступа браузера к камере/микрофону: <http://26.236.251.44:3000>;
- архив сертификата для первого входа друга: <http://26.236.251.44:3000/Yargram-HTTPS-Setup.zip>.

## Что работает

- регистрация без кода из почты, вход по email и пароль в виде bcrypt-хеша;
- профиль, уникальный `@username`, описание, аватар и просмотр профиля собеседника;
- личные диалоги, online/last seen, «Печатает…» и realtime-доставка;
- галочки отправки/прочтения, ответ, изменение, удаление, поиск, копирование и повтор отправки;
- фотографии до 20 МБ, произвольные файлы до 100 МБ, предпросмотр, прогресс и просмотрщик фото;
- файлы и аватары выдаются по временным подписанным ссылкам, срок и доступ проверяются сервером;
- реакции, эмодзи, Избранное, пересылка и несколько закреплённых сообщений;
- звуки, browser notifications, отключение уведомлений отдельного чата и архив;
- блокировка пользователей, список заблокированных и сохраняемые жалобы;
- WebRTC-аудио/видео, включение камеры во время звонка, демонстрация экрана, таймер, история звонков, выбор устройств и громкость 0–200%;
- светлая/тёмная тема и адаптивный web-интерфейс;
- постоянная локальная база с атомарной записью.

При `DATABASE_DRIVER=postgres` аккаунты и данные общения сохраняются в PostgreSQL. Без настройки PostgreSQL прежние установки используют `apps/server/data/yargram.json`. Загруженные фотографии, аватары и файлы лежат в `apps/server/data/uploads`; база хранит их метаданные и связи с сообщениями. Данные переживают сборку и перезапуск. После миграции старый JSON остаётся резервным снимком и больше не обновляется. Текущий медиапоток звонка и незавершённый текст в поле ввода не сохраняются.

Простой список возможностей без технических подробностей находится в `Функции Yargram.txt`.

## Самый простой запуск

Нужны Windows, Node.js 20 или новее, npm и активный Radmin VPN с адресом `26.236.251.44`.

1. Подключитесь к нужной сети Radmin VPN.
2. Дважды щёлкните `Запустить Yargram.bat`.
3. Подтвердите запрос UAC: он нужен только для точечных правил Windows Firewall на TCP `3000` и `3443`.
4. Первый запуск установит зависимости, соберёт проект, создаст локальный HTTPS-сертификат и откроет <https://26.236.251.44:3443>.
5. Не закрывайте отдельное окно сервера, пока Yargram нужен вам или другу.

Дополнительные файлы:

- `Проверить Yargram.bat` — проверка Radmin VPN, обоих портов, API, HTTPS, архива сертификата и Firewall;
- `Остановить Yargram.bat` — безопасная остановка только подтверждённого процесса Yargram.

Данные из `apps/server/data/yargram.json` при сборке и обычном перезапуске не удаляются.

## Как входит друг

Ничего отправлять вручную не требуется. Друг подключается к той же сети Radmin VPN и сам скачивает подготовленный публичный сертификат с вашего сервера:

1. открыть <http://26.236.251.44:3000/Yargram-HTTPS-Setup.zip>;
2. распаковать архив;
3. один раз запустить `Install-Yargram-Certificate.bat`;
4. перезапустить браузер;
5. открыть <https://26.236.251.44:3443>.

В публичном архиве нет закрытого ключа: только сертификат локального центра, установщик для текущего пользователя Windows и инструкция. Архив следует устанавливать только с этого конкретного компьютера владельца Yargram.

Подробная короткая памятка находится в `ИНСТРУКЦИЯ_ДРУГУ.txt`.

## Почему нужен HTTPS

Браузеры запрещают `getUserMedia` (камеру и микрофон) на обычном адресе `http://26...`. Поэтому HTTP `3000` оставлен для резервного входа и скачивания сертификата, а звонки работают через доверенный HTTPS `3443`.

HTTPS защищает web/API/Socket.IO. Сам медиапоток WebRTC идёт напрямую между браузерами через сеть Radmin VPN; для него используются ICE-кандидаты и публичный STUN-сервер. TURN в этой временной конфигурации не развёрнут, поэтому звонок рассчитан прежде всего на участников одной Radmin-сети.

## Команды разработчика

```powershell
npm.cmd install
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run smoke
npm.cmd start
```

`npm.cmd start` использует `scripts/start-yargram.ps1`. Скрипт создаёт `.env` со случайными JWT/TLS-секретами, при необходимости собирает workspace, обновляет публичный HTTPS-архив и запускает один процесс Node.js с двумя слушателями. Один экземпляр Socket.IO прикреплён к HTTP и HTTPS, поэтому realtime работает между обоими адресами.

`npm.cmd run smoke` запускает отдельный временный HTTP-сервер и временную базу, проверяет страницу и основной API-сценарий, затем удаляет только созданные им тестовые данные. Серверные тесты дополнительно проверяют загрузки, реакции, Избранное, архив, блокировки, жалобы, звонки и чтение новых данных после перезапуска базы.

Режим разработки:

```powershell
npm.cmd run dev
```

Vite доступен на <http://26.236.251.44:5173> и проксирует `/api` и `/socket.io` на backend `3000`. Для реальной проверки камеры и микрофона используйте production HTTPS-запуск.

## Структура

- `apps/web` — React/Vite-клиент;
- `apps/server` — Express, Socket.IO, WebRTC-сигнализация и JSON-база;
- `runtime/https` — сгенерированный закрытый PFX и публичный CA (игнорируется Git);
- `scripts/setup-https.ps1` — создание сертификатов и публичного архива;
- `scripts/open-firewall.ps1` — правила только для `26.236.251.44`, удалённых адресов `26.0.0.0/8` и TCP `3000/3443`.

Это временная Radmin-конфигурация, а не публичный production-хостинг. Для публикации в интернете потребуются домен, публичный сертификат, reverse proxy, резервное копирование и TURN-сервер.
