# Yargram 0.1 ЗБТ — мессенджер через Radmin VPN

Версия приложения остаётся **0.1** — так решено намеренно, пока не выйдут сборки для ПК и телефонов. При этом набор функций обновления «0.2» уже реализован: запись голосовых сообщений и видеокружков, папки чатов, черновики, отложенная отправка, приватность статуса посещения и административные права.

Документация: [docs/API.md](docs/API.md) — REST и Socket.IO, [docs/DATABASE.md](docs/DATABASE.md) — подключение и перенос данных, [docs/DEPLOY.md](docs/DEPLOY.md) — перенос на сервер (работа без своего ПК, звонки через TURN), [docs/ИНСТРУКЦИЯ_RAVEN.md](docs/ИНСТРУКЦИЯ_RAVEN.md) — перенос на бесплатный хостинг Raven Host, [docs/ROADMAP.md](docs/ROADMAP.md) — планы сайта, приложений, Telegram-входа, тем и личного чата, [docs/TELEGRAM-FEATURES.md](docs/TELEGRAM-FEATURES.md) — очередь этапов, [docs/agent-history](docs/agent-history/index.md) — выгруженная история разработки.

Версия в `package.json` — `0.1.0`, и она намеренно не поднимается до 0.2: «0.2» в названиях документов обозначает набор функций, а не номер сборки. В интерфейсе та же версия подписана как **0.1.0 ЗБТ** — закрытое бета-тестирование: сборка ещё не публичная, её показывают ограниченному кругу людей.

Для локальной PostgreSQL перед запуском Yargram откройте отдельный терминал и выполните `npm.cmd run db:local`. Первый перенос JSON при остановленном сервере: `npm.cmd run db:use-local`. Повторять импорт при каждом запуске не нужно.

Yargram запускается на Windows без Docker и временно доступен участникам одной сети Radmin VPN.

- адрес для друзей и переписки: <http://26.53.76.128:3000> — скачивать и устанавливать ничего не нужно;
- адрес для звонков: <https://26.53.76.128:3443> — работает, если установлен HTTPS-сертификат; другу тоже ничего скачивать не нужно.

## Что работает

- регистрация без кода из почты, вход по email и пароль в виде bcrypt-хеша;
- профиль, уникальный `@username`, описание, аватар и просмотр профиля собеседника;
- личные диалоги, online/last seen, «Печатает…» и realtime-доставка;
- галочки отправки/прочтения, ответ, изменение, удаление, поиск, копирование и повтор отправки;
- фотографии до 20 МБ, произвольные файлы до 100 МБ, предпросмотр, прогресс и просмотрщик фото;
- файлы и аватары выдаются по временным подписанным ссылкам, срок и доступ проверяются сервером;
- реакции, эмодзи, Избранное, пересылка и несколько закреплённых сообщений;
- звуки, browser notifications, отключение уведомлений отдельного чата и архив;
- блокировка пользователей, список заблокированных и сохраняемые жалобы;
- WebRTC-аудио/видео, включение камеры во время звонка, демонстрация экрана, таймер, история звонков, выбор устройств и громкость 0–200%;
- голосовые сообщения и видеокружки: запись с микрофона и камеры, автоматическая остановка кружка на 60 секундах, встроенный плеер;
- папки чатов, черновики недописанных сообщений и отложенная отправка с серверной очередью и отменой;
- скрытие статуса посещения: точное время, онлайн и приблизительные категории «недавно / на прошлой неделе / в прошлом месяце / давно»;
- административные права: владелец, отметка «проверен», бейдж Yargram, дополнительные username и управление закреплёнными аккаунтами;
- светлая/тёмная тема, выбор акцентного цвета и обои чата;
- знакомство со слайдами при первом заходе и несколько аккаунтов на одном устройстве с переключением в боковой панели;
- постоянная локальная база с атомарной записью.

При `DATABASE_DRIVER=postgres` аккаунты и данные общения сохраняются в PostgreSQL. Без настройки PostgreSQL прежние установки используют `apps/server/data/yargram.json`. Загруженные фотографии, аватары и файлы лежат в `apps/server/data/uploads`; база хранит их метаданные и связи с сообщениями. Данные переживают сборку и перезапуск. После миграции старый JSON остаётся резервным снимком и больше не обновляется. Текущий медиапоток звонка и незавершённый текст в поле ввода не сохраняются.

Резервные копии делает `scripts/backup.mjs`: база выгружается в JSON, вложения докачиваются в общее зеркало. Копия снимается раз в сутки при запуске (лаунчер, фоновым процессом), вручную — кнопкой `Сделать копию Yargram.bat` или `npm run backup`; `npm run backup:status` показывает, что уже есть. Копии старше недели удаляются автоматически. Восстановление — `node scripts/backup.mjs --restore runtime/backups/<дата>_<время>` (подробности в `README.txt` внутри копии). Копии лежат на том же диске, что и данные, поэтому от смерти диска они не спасут — для этого папку `runtime/backups` нужно увозить на другой носитель.

Простой список возможностей без технических подробностей находится в `Функции Yargram.txt`.

## Самый простой запуск

Нужны Windows, Node.js 20 или новее, npm и активный Radmin VPN с адресом `26.53.76.128`.

1. Подключитесь к нужной сети Radmin VPN.
2. Дважды щёлкните `Запустить Yargram.bat`.
3. Подтвердите запрос UAC: он нужен только для точечных правил Windows Firewall на TCP `3000` и `3443`.
4. Первый запуск установит зависимости, соберёт проект и откроет <http://26.53.76.128:3000>. Если HTTPS-сертификат подготовить не удалось, запуск всё равно считается успешным: переписка, файлы и фотографии работают, недоступны только звонки.
5. Не закрывайте отдельное окно сервера, пока Yargram нужен вам или другу.

Дополнительные файлы:

- `Проверить Yargram.bat` — проверка Radmin VPN, обоих портов, API, HTTPS, архива сертификата и Firewall;
- `Остановить Yargram.bat` — безопасная остановка только подтверждённого процесса Yargram.

Данные из `apps/server/data/yargram.json` при сборке и обычном перезапуске не удаляются.

## Как входит друг

Друг подключается к той же сети Radmin VPN и открывает обычную ссылку:

<http://26.53.76.128:3000>

Скачивать, распаковывать и устанавливать ничего не нужно: ссылка открывается в любом браузере сразу, и по ней доступны переписка, фотографии, файлы и остальные функции.

Звонки, видеокружки и голосовые сообщения браузер разрешает только на защищённом соединении, поэтому они требуют необязательного шага — открыть <https://26.53.76.128:3443>. Скачивать и устанавливать другу ничего не нужно: адрес открывается в браузере сразу, как и обычная ссылка.

Отдельного архива с сертификатом больше нет — установка сертификата на компьютер друга не требуется. Если звонки не нужны, второй адрес можно не открывать.

Подробная короткая памятка находится в `ИНСТРУКЦИЯ_ДРУГУ.txt`.

## Почему нужен HTTPS

Браузеры запрещают `getUserMedia` (камеру и микрофон) на обычном адресе `http://26...`. Поэтому HTTP `3000` оставлен для резервного входа и скачивания сертификата, а звонки работают через доверенный HTTPS `3443`.

HTTPS защищает web/API/Socket.IO. Сам медиапоток WebRTC идёт напрямую между браузерами через сеть Radmin VPN; для него используются ICE-кандидаты и публичный STUN-сервер. TURN в этой временной конфигурации не развёрнут, поэтому звонок рассчитан прежде всего на участников одной Radmin-сети.

## Команды разработчика

```powershell
npm.cmd install
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run verify
npm.cmd run check:ps
npm.cmd run build
npm.cmd run smoke
npm.cmd start
```

`npm.cmd run verify` — проверка перед коммитом: типы, линтер и все тесты сразу в обоих workspace.

`npm.cmd run check:ps` прогоняет все `scripts/*.ps1` через парсер Windows PowerShell 5.1 и требует UTF-8 BOM там, где встречается кириллица (без BOM PS 5.1 читает такой файл в ANSI).

`npm.cmd start` использует `scripts/start-yargram.ps1`. Скрипт создаёт `.env` со случайными JWT/TLS-секретами, при необходимости собирает workspace, обновляет публичный HTTPS-архив и запускает один процесс Node.js с двумя слушателями. Один экземпляр Socket.IO прикреплён к HTTP и HTTPS, поэтому realtime работает между обоими адресами.

`npm.cmd run smoke` запускает отдельный временный HTTP-сервер и временную базу, проверяет страницу и основной API-сценарий, затем удаляет только созданные им тестовые данные. Серверные тесты дополнительно проверяют загрузки, реакции, Избранное, архив, блокировки, жалобы, звонки и чтение новых данных после перезапуска базы.

Режим разработки:

```powershell
npm.cmd run dev
```

Vite доступен на <http://26.53.76.128:5173> и проксирует `/api` и `/socket.io` на backend `3000`. Для реальной проверки камеры и микрофона используйте production HTTPS-запуск.

## Структура

- `apps/web` — React/Vite-клиент: интерфейс мессенджера, звонки через WebRTC, темы и уведомления; отдаётся по `/app`;
- `apps/landing` — статический сайт о Yargram: описание возможностей и кнопка входа; отдаётся по `/`;
- `apps/server` — Express, Socket.IO, WebRTC-сигнализация, сервисы и два взаимозаменяемых хранилища (JSON-файл и PostgreSQL);
- `apps/server/tests` — серверные тесты, включая проверки на настоящем временном кластере PostgreSQL;
- `docs` — документация: API, база данных, планы и выгруженная история разработки;
- `runtime/https` — сгенерированный закрытый PFX и публичный CA (игнорируется Git);
- `runtime/postgres` — данные и пароль локального PostgreSQL (игнорируется Git);
- `scripts/setup-https.ps1` — создание сертификатов и публичного архива;
- `scripts/open-firewall.ps1` — правила только для `26.53.76.128`, удалённых адресов `26.0.0.0/8` и TCP `3000/3443`;
- `scripts/grant-owner.mjs` и `scripts/grant-badges.mjs` — выдача владельческих прав и бейджей.

Это временная Radmin-конфигурация, а не публичный production-хостинг. Для публикации в интернете потребуются домен, публичный сертификат, reverse proxy, резервное копирование и TURN-сервер.
