### 🔥 17:50 — ДВА ОТКРЫТИЯ: звонкам не нужен UDP-хостинг + Oracle-регистрация падает

1. **Звонки не требуют UDP на нашем сервере.** В коде уже есть поддержка
   **внешнего TURN** (`TURN_CREDENTIALS_URL`, `apps/server/src/lib/turn.ts` +
   `apps/web/src/features/calls/turnCredentials.ts`): сервер отдаёт браузеру
   временные реквизиты, медиа гоняет ЧУЖОЙ сервер (Open Relay/Metered —
   **20 ГБ/мес бесплатно**, порты 80/443, TCP+UDP). Наш хост только
   сигнализация (WebSocket) + раздача реквизитов. Значит **любой хостинг
   годится для звонков**, включая Raven. Требование «хостинг должен проводить
   звонки» устарело — достаточно бесплатного TURN-сервиса.
   - Metered free: signup `dashboard.metered.ca/signup?tool=turnserver` → API key.
   - Формат URL: отдаёт `{"iceServers":[…]}` (парсер понимает и массив).
2. **Oracle: регистрация падает** — `Email configuration error. Email verification
   link failed to send` на Gmail. Причины по докам: повторная попытка/rate-limit,
   VPN/прокси (у владельца curl ходит через `127.0.0.1:60554` — вероятно, и
   браузер тоже), уже созданный аккаунт, спам-фильтр, сбой на стороне Oracle.
   Лечение: войти (а не регистрироваться) на cloud.oracle.com; проверить
   спам/промо; подождать 10–30 мин; инкогнито без адблокеров; выключить
   VPN/прокси; другой браузер/почта.
3. Вывод: раз звонки решаются внешним TURN, вариантов больше. Лучшие:

### 🔥 19:50 — HTTPS на своём домене: причина 502 и включение прокси Cloudflare

1. **Пользователь включил прокси Cloudflare** (оранжевое облако). DNS теперь
   отдаёт 104.21.53.202 / 172.67.218.175 + IPv6, сертификат `CN=yargram.site`
   выдаёт Cloudflare. Но и https, и http на yargram.site отдавали **502**.
2. **Причина найдена за минуту** сравнением двух ответов самого origin:
   `curl -H "Host: yargram.site" http://147.124.213.50/` → **200**,
   `curl -k -H "Host: yargram.site" https://147.124.213.50/` → **502**.
   Значит Cloudflare в режиме SSL/TLS **Full** стучится на origin:443, где
   сертификата домена нет (там только `CN=*.app.ravenhost.space`).
   **Решение: SSL/TLS → Flexible** плюс «Always Use HTTPS». Разбор —
   `docs/ИНСТРУКЦИЯ_RAVEN.md`, новый раздел «HTTPS 502 при включённом Cloudflare».
3. В `runtime/env-for-server.txt` стоял `PUBLIC_ORIGIN=https://yargram.app.ravenhost.space`
   (старый поддомен) — **заменено на https://yargram.site**: от него зависят
   CORS, названия сеансов и ссылки на файлы.
4. Добавлена настройка **`FORCE_HTTPS`** (`apps/server/src/config.ts` плюс
   мидлварь в `app.ts`, по умолчанию **false**). Код ответа 301 для GET/HEAD и
   **308** для остального: 301 браузеры вправе применить к POST как GET, и тело
   бы потерялось. По умолчанию выключено намеренно — в режиме Flexible
   Cloudflare всегда ходит к нам по HTTP, и включённый редирект замкнул бы сайт
   в бесконечный цикл. Тесты — `tests/app.test.ts` (+2; харнесс `createHarness`
   принимает второй аргумент `extraEnv`).
5. **PWA-установка**: `useInstallPrompt` (состояние на уровне модуля — событие
   приходит до монтирования React и внутри эффекта было бы потеряно),
   `InstallScreen` (три состояния: доступно / уже установлено / вручную для iOS),
   раздел «Установить приложение» в настройках. `beforeinstallprompt` обязан
   вызывать `preventDefault()` — иначе браузер покажет свой опросник сам, а
   сохранённое событие станет недействительным.
6. Проверки: сервер **211/211**, веб **583/583**, eslint и typecheck чисты.
   **Грабля при сборке:** `npm run build` падает на
   `SAFE_DELETE_BULK_CONFIRM_REQUIRED` (vite не может очистить `apps/web/dist`)
   — обходится переносом папки `dist` в `runtime/` перед сборкой. То же для
   лендинга и сервера.

### 🔥 22:25 — Уточнение диагноза: на origin порт 443 мёртв для ВСЕХ хостов

Приложение запущено, `http://yargram.site/` отдаёт 200, `https://` — 502.
Режим Cloudflare **всё ещё Full** (переключить может только владелец).

**Новое и важное.** Порт 443 на этом сервере отдаёт `502` **любому** имени,
включая родной поддомен Raven:

- `-H "Host: yargram.app.ravenhost.space" https://147.124.213.50/` → **502**
- `-H "Host: random.example"` → тоже **502**
- сертификат по любому SNI = `CN=*.app.ravenhost.space` (Let's Encrypt)

То есть TLS на origin не работает **вообще**, и режимы `Full` / `Full (strict)`
обречены на 502 в принципе — дело не в нашем домене и не в отсутствии
сертификата только у него. Родной поддомен Raven ведёт себя так же: по HTTP
отдаёт `301` на HTTPS, а по HTTPS — `502`. **Рабочий режим на этом тарифе
только один — `Flexible`.**

**Проверка, что вход не сломается.** Yargram передаёт токен заголовком
`Authorization: Bearer …` (`apps/server/src/http/auth-middleware.ts`), а не
cookie; `cookie-parser` не подключён, флагов `Secure` в проекте нет. Поэтому
«http» внутри цепочки Cloudflare → origin ничего не ломает: браузер общается с
Cloudflare по HTTPS. Единственная видимая мелочь — в «Активных сеансах» сайт
может определиться как `http://yargram.site` (`siteFrom` строит название из
`request.protocol`, а за Flexible он всегда `http`).

**Новый инструмент — `scripts/check-host.mjs`** (npm-скрипт `check:host`).
Одной командой проверяет DNS, признак прокси Cloudflare, ответы снаружи по
http/https, ответы origin по портам 80/443/порта приложения и раздачу файлов
PWA; сам ставит диагноз и печатает лечение. Запуск:
`node scripts/check-host.mjs --origin 147.124.213.50`.

**Грабля при написании:** `fetch` в Node не даёт подставить `Host` (заголовок
запрещён) — в скрипте используется `node:http`/`node:https` `request`. Ещё:
признак «это приложение, а не заглушка» ищется в первых 600 символах ответа —
на 200 символах `Yargram` (позиция 249) не находился и диагноз не срабатывал.
