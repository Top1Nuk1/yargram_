# 7 октября 2026

## Что просил пользователь

1. «кстати баг в app: **An unexpected server error occurred**» — воспроизвести и починить.
2. «продолжи» — довести разбор до конца (плюс вводная: он вставил вывод cmd, где `grep` на
   Windows отсутствует — поиск я взял на себя).

## Откуда берётся строка

Ровно **два** источника (поиск по `apps/`):

- `errorHandler` в `apps/server/src/lib/errors.ts` → HTTP **500** `INTERNAL_ERROR`;
- `formatSocketError` в `apps/server/src/realtime/socket-server.ts` → сокет `INTERNAL_ERROR`.

Оба логируют настоящую причину в консоль через `console.error` и только клиенту отдают маску.

## Причина (найдена, а не угадана)

Express сам бросает `URIError: Failed to decode param '%'` на **кривом percent-коде в пути**
(`/api/users/%`, `/api/users/%ZZ`, `/app/%E0%A4%A`) и подписывает его `status: 400`,
`statusCode: 400`. Старый `errorHandler` распознавал только `ZodError` (400), `SyntaxError`+400
(`INVALID_JSON`), `AppError` и `413` — всё остальное падало в ветку 500. Отсюда и «An unexpected
server error occurred» при полностью клиентской ошибке. Тот же дефект был у статики
(`Forbidden`/`Not Found` → 403/404).

🔥 **Методика поиска**: сообщение по замыслу скрывает причину, поэтому логи бесполезны — надо
строить **свипы API**, записывая статус каждого запроса, и коррелировать с логом сервера.
Свипы (`runtime/bug500/`): `sweep.mjs` (127), `sweep-edge.mjs` (84), `sweep-support.mjs` (49 + сокет),
`sweep-more.mjs` (64), `sweep-uri.mjs` (42). Ноль 500 во всех областях, кроме `sweep-uri` —
там **12 × 500** и в логе `URIError: Failed to decode param … { statusCode: 400, status: 400 }`.
Итоговая приёмка: `{"200":9,"400":12,"401":19,"403":2}`, «находок нет».

## Правка

- **`apps/server/src/lib/errors.ts`** — новая ветка после 413: `clientErrorStatus(error)`
  (числовой `status`/`statusCode` в 400–499) → ответ **готовым 4xx** и без `console.error`
  (это не сбой). Код: `URIError` → `INVALID_URL`, 400→`BAD_REQUEST`, 403→`FORBIDDEN`,
  404→`NOT_FOUND`, 429→`TOO_MANY_REQUESTS`, иначе `HTTP_${status}`. Сообщение —
  `STATUS_CODES[status] ?? "Request failed"`: **текст ошибки не эхоим**, чтобы не слить
  внутренности. Настоящие сбои по-прежнему 500 `INTERNAL_ERROR`.
- **`apps/server/tests/app.test.ts`** — два регресс-теста: 6 кривых путей → 400 `INVALID_URL`
  без «unexpected» в тексте; и min-апп, доказывающий, что 403 проходит наружу как 403, а
  `throw new Error` остаётся 500 `INTERNAL_ERROR`.

## Грабли стенда (воспроизведены заново)

- `NODE_ENV=production` обязателен: без него статика и catch-all **не регистрируются вообще**
  — все страницы 404.
- В production `loadConfig` отказывается стартовать с дефолтными `JWT_SECRET`/`DB_ENCRYPTION_KEY`.
- `import "dotenv/config"` ищет `.env` **относительно cwd** → запуск из `apps/server` не грузит
  ничего; нужен корень проекта (или явный export).
- `pg_dump` нет → копия логическая; для свипов по Postgres создавал одноразовую БД
  `yargram_sweep` в кластере пользователя (`127.0.0.1:55432`), схема создаётся сама.
- Инструменты сессии: `run_in_background` принимает только boolean; `nohup`/отвязанные дети
  умирают вместе с шеллом; PowerShell-инструмент не отдаёт вывод; длинные пайпы рвутся по
  SIGTERM → **все запуски — одним форграунд-скриптом**, который ждёт `/api/health`, печатает
  лог и снимает **только порт 3100** (`taskkill`). `grep` в cmd у пользователя отсутствует.
- «Служебная группа не видна владельцу» — артефакт моей же заготовки данных (владелец ранее
  вышел из группы, `leftIds`), а не баг продукта.

## Статус

Пользователю нужно **пересобрать `dist` и перезапустить лаунчер** — правка живёт в серверном
коде. Версия `0.1.0` не менялась.

# Второй «An unexpected server error occurred» (после percent-фикса)

Симптом тот же, а причина **другая**: percent-фикс в `lib/errors.ts` уже в проде
(`dist/lib/errors.js` собран до старта процесса), значит это самостоятельный баг.

## Диагностика

- Свип живого сервера (`runtime/bug500/sweep-live.mjs`, свой JWT, только GET):
  `{"200":23,"500":2}` → `/api/favorites`, `/api/support`, позже пал и `/api/conversations`.
- Лог сервера никуда не пишется (лаунчер открывает окно без редиректа) → написал
  **in-process трассер** `runtime/bug500/trace-live.mjs`: импортирует `dist/*`, поднимает
  продовый конфиг (`dotenv` + `loadConfig` + `openStorage`) и дергает те же сервисы.
  Стоп-трейс однозначный:
  `TypeError: Cannot read properties of undefined (reading 'length')` в
  `ChatService.toMessageSnapshot` → `stickerIds.length > 0`.

## Корень

- В проде **66 из 66** сообщений без ключа `stickerIds` (строки до фичи стикеров);
  `poll`/`replyToId` тоже отсутствуют, остальные дефолты на месте.
- **JSON-драйвер** прогоняет записи через Zod (`messageSchema`):
  `stickerIds/attachmentIds/reactions` → `.default([])`, `readBy` → `[senderId, ...]`,
  `kind` → `"user"`, плюс дедупликации. Поэтому там ничего не падало.
- **Postgres-драйвер** отдаёт `payload` как есть (общие `select`/`find` без нормализации) —
  ровно зеркальная половина грабля «JSON молча вырезает поля».

## Фикс (3 точки)

1. `apps/server/src/repositories/postgres-repositories.ts` — `normalizeMessage()` применяется
   в `select()` для таблицы `messages` (т.е. во **всех** путях чтения: `findById`,
   `listForConversation`, `listByIds`, `findByAttachmentId`, `markRead`, `mutate`);
   нормализуется и обратная запись → legacy-строки «залечиваются» при первом же апдейте.
2. `apps/server/src/services/chat-service.ts` — страховка: деструктуризация со значениями
   по умолчанию (`stickerIds = []`, `reactions = []`) в `toMessageSnapshot` и
   `placeholderSnapshot`, плюс `message.attachmentIds ?? []` в `findManyByIds`.
3. `apps/server/tests/postgres.test.ts` — регрессия: вставляет строку напрямую в `messages`
   (только `id/conversationId/senderId/text/createdAt`) и проверяет нормализацию чтением
   `findById`/`listForConversation`/`listByIds`, мутацию `setReaction` и то, что
   `ChatService.listConversations/listFavorites` не бросают.
