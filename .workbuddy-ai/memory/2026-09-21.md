# 2026-09-21 — Yargram

## Изучение проекта (первый проход)

Yargram — мессенджер для сети Radmin VPN (26.236.251.44). Monorepo npm workspaces:
- `apps/web` — React 19 + Vite 7 + Tailwind 3 + socket.io-client, ~9.8k строк. Монолит
  `features/messenger/MessengerScreen.tsx` (2823 строки) и `features/calls/useWebRtcCall.ts` (1815).
- `apps/server` — Express 4 + Socket.IO 4 + Zod + bcryptjs + jsonwebtoken, ~6.5k строк. Один процесс,
  два слушателя HTTP 3000 / HTTPS 3443, один экземпляр Socket.IO на оба.
- Хранилище абстрагировано: `repositories/json-repositories.ts` (881) и `postgres-repositories.ts` (532),
  выбор через `DATABASE_DRIVER`/`DATABASE_URL`. Медиа — файлы в `apps/server/data/uploads` по временным
  подписанным ссылкам (JWT, TTL 24 ч).
- `scripts/` — PowerShell-обвязка (сертификаты, Firewall, embedded-postgres, smoke), запуск через 3 `.bat`.

В коде есть то, чего нет в README: папки чатов, черновики, отложенная отправка, запись голосовых и
видеокружков, админ-слой (`isOwner`, `isVerified`, `badge: yargram`, `adminUserIds`, бан/заморозка, `/admin/*`).

Расхождения документации: `docs/DATABASE.md` говорит про «семь таблиц», а в схеме уже есть `folders`,
`scheduled_messages` и др. README не знает про папки/черновики/отложенную отправку. `Обновления.txt` —
это вставленный промпт ТЗ 0.2, а не список изменений. Репозиторий не под git.

## Ловушка запуска: админские права ломают PostgreSQL

`scripts/launch-yargram.ps1` всегда поднимает себя через UAC (`-Verb RunAs`), и окно сервера
тоже стартует **с повышенным токеном**. А `embedded-postgres` (в `ensure-postgres.mjs` →
`local-postgres.mjs`) отказывается работать под админом:

```
Execution of PostgreSQL by a user with administrative permissions is not permitted.
```

- Админ нужен только `scripts/open-firewall.ps1` (шаг 2/4). Сертификаты в `setup-https.ps1`
  кладутся в `Cert:\CurrentUser\My` — права не нужны. Значит серверу повышение не требуется.
- Обходной путь: в **обычном** (не админском) терминале запустить `npm run db:local` и оставить
  окно открытым, потом запускать батник — `ensure-postgres.mjs` увидит живой 127.0.0.1:55432 и
  пойдёт по быстрой ветке. Именно так всё работало 20.09.
- **Фикс сделан, коммит `d5d0b25`.** `launch-yargram.ps1` больше не повышает себя: идёт без
  повышения, а остановку прежнего экземпляра + файрвол делает новый повышенный процесс
  `scripts/prepare-yargram-access.ps1` (один UAC вместо повышения всего запуска). Если батник
  всё же запущен от админа — лаунчер говорит об этом прямо. `start-yargram.ps1` распознаёт
  ошибку про `administrative permissions` и подсказывает правильный запуск.
- Заодно `.gitignore`: `runtime/` игнорируется целиком (там только генерируемые артефакты,
  в git не отслеживалось ничего — проверено через `git ls-files runtime/` = 0).
- **Важно при правках PowerShell в этом проекте:** все `.ps1` лежат в UTF-8 **с BOM**, иначе
  PS 5.1 читает кириллицу как ANSI и ломает сообщения. После записи файла пересохранять через
  `[System.IO.File]::WriteAllText($p, $text, (New-Object System.Text.UTF8Encoding($true)))`.
  Синтаксис проверять так: `[System.Management.Automation.Language.Parser]::ParseFile(...)`.

- **Коммит `a585f82`:** тесты для UserName (6 штук: имя без значков, каждый значок по отдельности,
  оба вместе, неизвестный badge, у галочки подъём больше, чем у звезды) + `.gitattributes`. В
  gitattributes побеждает последнее подходящее правило — общая строка должна быть первой, иначе
  `*.bat/*.ps1 eol=crlf` затирается общим `eol=lf`. Теперь в коммитах не сыпятся предупреждения
  «LF will be replaced by CRLF».
- **Коммит `1ed256c`:** аватары в сообщениях на десктопе. В `<li key={message.id}>` считаем
  `isLastOfGroup` (нет следующего сообщения, или следующий день, или другой отправитель, или
  системное). Аватар 36×36 слева от пузыря (`hidden md:block`, `w-9 shrink-0`) показывается
  только у последнего сообщения подряд идущей группы — так аватар «уходит вниз», когда человек
  пишет дальше. Свои сообщения — без аватара. Тесты: 47 зелёных (25 сервер + 22 веб: было 34,
  +13 новых).
  - Peer-профиль (`MessengerModals.PeerProfileModal`): заголовок = `@username` (или displayName
    если нет), под ним — «а также …».
  - Свой профиль (`ProfileModal.tsx` «Ваш аккаунт»): заголовок остался displayName (это
    редактируемое поле), под `@username` добавлена строка алиасов.
  - В `AdditionalHandles` фильтруем основной `@username` из списка, чтобы не было дубля
    `@monk` + `а также @monk` если админ зачем-то продублировал.
- **Коммит `b06400f`:** группировка сообщений по зазорам. В `<ol>` убран `gap-1.5`, на каждом `<li>`
  считаем `sameGroupAsPrevious` (нет предыдущего, или разный день/автор/тип) и ставим `mt-0.5`
  внутри группы или `mt-3` между группами. Работает для входящих и своих — кучка сообщений
  склеивается, аватар у последнего, между разными авторами виден зазор.
- **Коммит `f9f02bd`:** клик по аватару в сообщении открывает модалку профиля (`setPeerProfileOpen(true)`),
  как в Telegram Desktop.

## Блокировка по-телеграмовски (коммит 9110f7b)

- Разделили направления: `blockedByMe` (я заблокировал) и `blockedByPeer` (меня заблокировали),
  старый `blocked` оставлен для совместимости.
- `assertNotBlockedByMe` — слабая проверка для сообщений/черновиков/отложенных: писать можно,
  если заблокировали *меня*. Для звонков осталась взаимная `assertUsersCanInteract`.
- Сообщения от заблокированных мною не отдаются: фильтр в `listMessages`, в `lastMessage`

- После разблокировки старые сообщения НЕ доставляются (выбор пользователя = как в Telegram).
- Приватность: `toPublicUserFor(user, viewerId)` скрывает аватар и время визита

  Применяется в `members`, поиске `/users` и `GET /users/:id`.
- Клиент: ввод закрывает только `blockedByMe`; по `blockedByPeer` точка «в сети» гасится.

## Грабли инструментов

- Python в Windows-режиме текста пишет `\n` как CRLF: после правок через `io.open(..., 'w')`
  файл целиком становится CRLF, хотя `.gitattributes` требует LF. Пересохранять в бинарном режиме.

## Админка: состояние цели, права, presence (коммит 313ca50)

- `DELETE /admin/:userId/assign` + `AdminService.unassignAdmin` снимают права администратора
  (раньше была только выдача). Кнопка «Снять права админа» в панели.
- Кнопка «Показать состояние»: ищет цель через `/api/users?q=`, показывает галочку/значок и
  список доп. юзернеймов, каждый из которых убирается отдельной кнопкой (пересчёт списка на клиенте).
  После любой админской правки панель обновляется ответом сервера.
- Presence: `online` в стартовом снимке считался как `lastSeenAt !== null` — то есть почти все
  подряд считались «в сети». Теперь по живым сокетам, но с оговоркой: у кого `lastSeenStatus`
  задан (скрыл время визита), тот онлайн не светится — иначе ломается приватность.
- Обработка presence вынесена из MessengerScreen в `lib/conversation.ts` (`updateConversationPresence`)
  и покрыта тремя тестами: онлайн, «был(а) сегодня в …», чужие участники не трогаются.
- Офлайн приходит с задержкой: `pendingWork.schedule(..., 3_000)` в обработчике disconnect.

## Юзернеймы без учёта регистра

Просьба: большие буквы в юзернейме должны «считаться», человека должно находить по любому из
его ников и в любом регистре. По факту поиск на сервере уже был регистронезависимым
(JSON: `toLowerCase()` по обе стороны; PostgreSQL: `username_key = lower($1)`), а вот
**доп. юзернеймы принудительно lowercase-ились** при выдаче — «Kotik» превращался в «kotik».

- `AdminService` (+ helper `normalizeHandles`): регистр доп. ников сохраняется как ввёл человек;
  чистим только пробелы и `@`; дубли внутри одного запроса склеиваются без учёта регистра;
  ник, совпадающий с собственным основным (`Top1Nuk1` и `top1nuk1`) — 409 USERNAME_TAKEN.
- `postgres-repositories.findByUsername`: доп. ники ищем через
  `EXISTS (... jsonb_array_elements_text ... WHERE lower(alias) = lower($1))` вместо
  `payload->'usernames' ? lower($1)` — старый оператор `?` требовал, чтобы алиасы лежали строго
  в нижнем регистре, и перестал бы работать теперь.
- Схема `/admin/:userId/grant`: `usernames` теперь массив `usernameSchema` (латиница/цифры/_, 3–32),
  раньше принимал любую строку (кириллица, пробелы).
- Клиент: `AdditionalHandles` сравнивает основной и доп. ники без регистра (иначе дубль `@Monk`);
  `UserSearchModal` показывает найденный alias (а не только основной ник) и больше не скрывает
  людей без основного ника; подсказки в профиле и поиске намекают, что регистр не важен.
- Тесты: новый «treats usernames as case-insensitive everywhere» (регистрация с `Top1Nuk1`, выдача
  `MiXeD_Alias`, поиск в 9 написаниях, цель в админке по нику с `@`, 409 на занятый адрес, 400 на
  кириллицу) + «finds a user by any username spelling, including mixed-case aliases» в
  `postgres.test.ts` (проверяет новый SQL на настоящем кластере). Обновлены два старых ожидания
  `["kotik", …]` → `["Kotik", …]`. Сервер 36 тестов, веб 71.

## Редизайн в стиле Telegram Desktop (коммит 1b81ccb)

Пользователь дал скриншоты ТГ-десктопа и попросил «переделать всё»: левая панель,
свой профиль, профиль чужого юзера. Без телефонов.

- **Сайдбар (`features/sidebar/AppSidebar.tsx`):** выезжает слева поверх списка
  диалогов. Шапка с аватаром/именем/«Установить эмодзи-статус», переключатель аккаунтов
  (текущий + заглушка «Добавить аккаунт» с пометкой «Скоро»), меню: Мой профиль,
  Кошелёк, Создать группу, Создать канал, Контакты, Звонки, Избранное, Закладки,
  Настройки, переключатель «Ночной режим», подвал «Yargram Desktop / Версия / О программе».
  Открывается из кнопки-«гамбургера» в шапке списка диалогов.
- **Профили (`features/profile/UserProfileSheet.tsx`):** единый лист с режимами
  `own | peer | public`. Telegram-секции: аватар + имя/галочка/значок + статус; ряд
  «Чат / Звук / Звонок / Ещё» (peer); био; `@ник + Имя пользователя + копирование`;
  «а также @alt»; день рождения (дата + «(N лет/года/лет)»); подарки; архив историй;
  для public — «публикации» и «подарки»; для peer — медиа-счётчики (фото/видео/файлы/
  аудио/ссылки/опросы/голосовые/GIF/общие группы, все 0 пока); контекстное меню
  «Поделиться контактом / Изменить контакт / Удалить контакт»; красная кнопка
  «Заблокировать»/«Разблокировать» + жалоба.
- **`birthday?: string` (YYYY-MM-DD):** поле в `User`/`PublicUser`/`CurrentUser`,
  `UpdateUserInput`, `updateProfileSchema`, json/postgres репозиториях и JSON-валидаторе.
  null на /users/me сбрасывает поле.
- Старый `PeerProfileModal` из MessengerModals больше не открывается из мессенджера —
  заменён на `UserProfileSheet` (но экспорт сохранён, чтобы ничего не сломалось в импортах).
- Заодно убрал мёртвый код из MessengerScreen: выпадающее меню профиля, неиспользуемые
  импорты (`FileText`, `Volume2/VolumeX`, `setSoundEnabled`, `browserNotificationPermission`,
  `requestBrowserNotificationPermission`, `profileMenuOpen`).
- Логика: Закладки из старого меню → «Закладки» в сайдбаре (заметки); Избранное →
  «Избранное» (saved conversation); Настройки → открывает существующую ProfileModal с
  табами (Аккаунт/Приватность/Оформление/Уведомления/Админ); Мой профиль → Telegram-лист.
- Превью в `runtime/design-preview/telegram-redesign.html` (в .gitignore).
- typecheck/lint чисто, тесты 36+71 без изменений.
