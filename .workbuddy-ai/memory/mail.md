# Yargram — почта и код из письма

- 🔥 **Письмо с кодом рисует «плашку» вёрсткой, а не картинкой** (`buildCodeHtml` в
  `mail-service.ts`): картинку нельзя выделить и скопировать, а часть почт прячет
  изображения до «показать». Разрядку цифр делает `letter-spacing` (не пробелы —
  они уедут в буфер). `<img>`, `<svg>`, `background-image` в письме запрещены:
  вырезает Outlook. Тесты — «HTML письма с кодом» в `tests/mail-service.test.ts`.
  **Исключение — единственная картинка, значок, и она едет вложением `cid:`** (своего
  публичного HTTPS-адреса у проекта нет → ссылка не загрузится ни у кого).
- 🔥 **Значок — `logo-plate.png`** (`apps/server/assets/`), имя задано `LOGO_FILE` в
  `mail-service.ts`. Это логотип целиком: иконка на мягкой плашке рядом со словом «Yargram».
  Порядок путей в `readLogo()`: сначала `dist/services → dist/assets` (сборка
  самодостаточна), потом `src/services → apps/server/assets` (разработка). Оба считаются
  **от файла**, не от `process.cwd()` — сервер запускают из корня проекта.
  🔥 Раньше путь вёл только в `apps/server/assets`, поэтому `copy-server-assets.mjs`
  копировал картинку в `dist/assets` зря, сервер её не читал. Стережёт тест «берёт значок
  из своих же ассетов» (пропускается, если `dist` не собран).
- **Флоу регистрации целиком** (согласован 02.10.2026): почта+пароль → аккаунт создаётся
  неподтверждённым → код на почту → **10 минут** на ввод (`EMAIL_CODE_TTL_SECONDS=600`) →
  можно отправить заново. На шаге ввода кода клиент показывает срок действия и пометку
  «проверьте папку Спам» (`auth.codeSpamHint`) — письма с кодом часто уходят в спам.
- Транспорт — `services/mail-service.ts`, провайдер из env. `MAIL_DRIVER=console` (**по умолчанию**)
  печатает письмо в лог (работает без SMTP и домена); `smtp` — nodemailer; `none` — выключено.
- 📮 **Запасные ящики** (03.10.2026) — чтобы код приходил, даже если Google заблокирует основной
  ящик. `config.mail.accounts: MailAccount[]` (`{user, pass, from}`), ключи `MAIL_USER`/`MAIL_PASS`/
  `MAIL_FROM` и `_2`, `_3` (адрес `_2/_3` **обязателен**: ящик другой). Заполнены два:
  `yargram.support@gmail.com` (основной) и `yarikgram@gmail.com`.
  🔥 **Два разных случая отказа, и путать их нельзя** (решение владельца 03.10.2026):
  1. **Ящик отказал** (пароль, блокировка, сеть) — ошибка видна сразу, письмо уходит со следующего
     **в том же запросе**: человек получает код как обычно, нажимать ничего не надо.
  2. **Ящик письмо принял, а оно не дошло** (спам, потеря) — ошибки нет, сервер узнать не может;
     единственный сигнал — человек нажал «отправить снова». Ради этого **повтор идёт со следующего
     ящика**: иначе повтор пошёл бы тем же путём в ту же «Спам». Это и просил владелец: первый код с
     первого ящика, повтор — со второго.
  Механика в `MailService`: `lastUsedIndex` (кто отправил последнее письмо) + `failedUntil`
  (индекс → до какого времени не выбирать стартовым, `RETRY_AFTER_MS` = 10 мин) + `chooseStart(rotate)`.
  Обычная отправка всегда стартует с **основного** (`0`), повтор — с `(lastUsedIndex + 1) % N`;
  отказавший ящик не выбирается стартовым 10 минут, но через 10 минут его снова попробуют (пароль
  могли вернуть). 🔥 Без этого сломанный основной стоил бы таймаута на **каждом** письме.
  Перебор внутри одного вызова остался — отказ ящика не превращается в «письмо не пришло».
  Признак повтора приходит из `AuthService.resendCode` → `issueCode(..., { rotate: true })`;
  первая отправка (регистрация/вход/сброс) — без него. Все упали — ошибка «не сработал ни один из N».
  Логи: `[mail] ящик … не отправил письмо`, `[mail] письмо ушло с запасного ящика …`,
  `[mail] повторная отправка — начинаем с ящика …`.
  Тесты: `tests/mail-fallback.test.ts` (11 сервисных + 4 конфиг; проверяет и **отправителя** — `from`
  того ящика, что реально отправил) и `tests/email-code.test.ts` («повторная отправка помечена как
  повтор, а первая — нет»). Невакуозность проверена: с выключенным поворотом падают 3 теста, без
  пропуска отказавшего — 2, без `rotate` в `resendCode` — 1.
  `set-mail-password.mjs` спрашивает слот 1/2/3; `test-mail.mjs`/`send-code-mail.mjs` печатают
  основной и запасные ящики и порядок отправки.
- **`EMAIL_CONFIRMATION` ВКЛЮЧЁН** (с 28.09.2026) — код при регистрации, входе И сбросе пароля.
  🔥 Проверки `emailVerified` при входе **нет**: код нужен всегда, поэтому аккаунт с мёртвой почтой
  теряет доступ навсегда. Аварийный выход: `MAIL_DRIVER=console` + рестарт → код печатается в окно
  сервера. Код — 6 цифр на **`User`** (`emailCodeHash` bcrypt, `emailCodePurpose/ExpiresAt/Attempts`),
  TTL `EMAIL_CODE_TTL_SECONDS` (600 с), гаснет после 5 неверных; назначение проверяется. Ручки
  `/auth/confirm-code`, `/auth/resend-code`, `/auth/reset-password/{request,confirm}`. Клиент —
  `AuthScreen` (`login|register|reset`), признак второго шага `'status' in result`.
- 🔑 **Проектный ящик — `yargram.support@gmail.com`** (точка в логине незначима). `.env` настроен
  (`MAIL_DRIVER=smtp`, `smtp.gmail.com:587`, `MAIL_SECURE=false`), пароль приложения вписан, проверено.
- Скрипты: `Вписать пароль почты.bat` / `npm run mail:password` (без эха, пишет `MAIL_PASS` +
  `MAIL_DRIVER=smtp`); `npm run mail:test -- адрес` (нужен свежий `npm run build`, `ИНСТРУКЦИЯ_ПОЧТА.txt`);
  **«Проверить письмо с кодом.bat»** / `npm run mail:code [-- адрес вид код]` —
  `scripts/send-code-mail.mjs`: спрашивает почту и вид письма (регистрация / вход / сброс), печатает
  настоящее письмо через тот же `MailService.sendCode` (код не проверяется, в базу ничего не пишется),
  код можно задать или взять случайный. Тоже берёт `apps/server/dist` → после правок письма нужен
  `npm run build`. Кнопка «Вписать пароль почты.bat» описана ниже;
  `set-user-account.mjs <ник> [--email=] [--password=] [--verify|--unverify] [--list]` (**почту нельзя
  сменить через API**; пароли только bcrypt; занятый адрес `23505`); `delete-user.mjs <ник>… [--restore]
  [--as=] [--dry-run]` — поднимает сервисы из `apps/server/dist` и зовёт `AdminService.deleteUser`
  (удаление каскадное, в SQL разъехалось бы).
- 🔥 **Жёсткая чистка («как будто не существовало») — только с бэкапом.** Аудит следов → копия в
  `runtime/backups/purge-<stamp>/` (`readable.json` через `AtRestCrypto` + `raw-rows.json`) → удаление
  от листьев к корню (`messages` → `conversations` → `attachments` → `users`) → проверка, что ники и
  почты свободны. Постоянного инструмента **намеренно нет**. ⚠️ Чат удаляемого с **реальным** аккаунтом
  исчезает и у него.
- **Провайдеры:** без домена надёжно только **пароль приложения своего ящика**. SMTP2GO (с 11.04.2025)
  требует подтверждённого отправителя, `Single sender` не годится для Gmail/Outlook/Yahoo (DMARC); те
  (с 02.2024) требуют SPF/DKIM. Яндекс `smtp.yandex.ru:465` (`MAIL_SECURE=true`), Gmail 587 (2FA).
  С доменом — Sender domain в SMTP2GO, порт 2525; `noreply@` для кодов, `support@` для ответов.
