# Скриншоты интерфейса Yargram

## Когда применять

- Нужно показать пользователю, как выглядит экран, до того как он запустит приложение.
- Проверка вёрстки, тёмной темы, нового экрана.
- Сервер пользователя (`Запустить Yargram.bat`, порты 3000/3443) **не трогаем** — стенд отдельный.

## Шаги

### 1. Собрать веб

```bash
cd C:/Games/YarGram && npm run build --workspace @yargram/web
```

Если сборка падает на `emptyDir` / `rmSync` (`node-safe-delete-shim`) — запущенный сервер держит
файлы `apps/web/dist`. Повторить запуск, при повторной неудаче попросить пользователя закрыть окно
сервера (лаунчер сам останавливает прежнюю версию перед сборкой).

### 2. Поднять стенд отдельной фоновой задачей

```bash
cd C:/Games/YarGram && HTTPS_PORT=0 PORT=3100 NODE_ENV=production DATABASE_DRIVER=json DATA_DIR=runtime/screenshot-preview/<папка> node apps/server/dist/index.js
```

Запускать **именно отдельной фоновой задачей**, а не `(node … &)` внутри другой команды: процесс
умирает вместе с родительской задачей.

Два обязательных переопределения:

- `DATABASE_DRIVER=json` — в корневом `.env` прописан postgres, иначе `ECONNREFUSED 127.0.0.1:55432`;
- `HTTPS_PORT=0` — в `.env` включён HTTPS на 3443, а там сервер пользователя, иначе
  `EADDRINUSE 0.0.0.0:3443`. Пустая строка **не подходит** (схема прогоняет её через
  `emptyStringToUndefined`), нужен именно `0`.

Дождаться готовности — опрос `fetch('http://127.0.0.1:3100/api/health')` в цикле.

### 3. Запустить сценарий съёмки

Готовые сценарии в `runtime/screenshot-preview/`: `shots-onboarding.mjs`, `shots-accounts.mjs`,
`shots-accounts-add.mjs`, `shots-admin-panel.mjs`, `shots-group-marks.mjs`, `shots-frozen.mjs`,
`shots-scam.mjs`, `shots-version.mjs`, `shots-groups.mjs`, `shots-polls.mjs`, `shots-deadline.mjs`,
`shots-tags.mjs`, `shots-unread.mjs`, `shots-removed.mjs`, `shots-restore.mjs`, `shots-live.mjs`,
`shots.mjs`.

Если сценарий вызывает `Page.navigate` в одном домене много раз и подставляет в
страницу большой блок `HELPERS`, объявляй в нём константы через `var`, а не `const` —
скрипт исполняется в одном контексте, и повторное `const` роняет всё с
`SyntaxError: Identifier 'PANEL' has already been declared`.

Новый сценарий делать по образцу `shots-onboarding.mjs` (там же хелперы `openApp`, `clickByText`,
`shot`). Данные для входа готовят `seed-*.mjs`, либо аккаунт создаётся через `POST /api/auth/register`.

### 4. Остановить стенд

Скриншоты сняты → погасить фоновую задачу. Стенд — не приложение пользователя, оставлять его нельзя.

## Правила

- **Серверную логику быстрее проверить без браузера.** `runtime/screenshot-preview/probe-usernames.mjs`
  сам поднимает стенд на порту 3101, делает первый аккаунт владельцем правкой `yargram.json`
  (с перезапуском) и гоняет сценарии через API, печатая статусы. Так разбирался случай
  «пропадают юзернеймы» — до всякой вёрстки.

- **Профиль Chrome общий:** `chrome-profile` (плюс `-2`…`-6`, `-groups`, `-polls`, `-tags`,
  `-unread`). Новые копии по 50 МБ не создавать. Перед съёмкой знакомства нужен `localStorage.clear()`,
  иначе флаг `yargram.onboardingDone` скроет слайды.
- **Готовый датасет `runtime/screenshot-preview/data` уже содержит владельца:** `Алиса`
  (`alice@preview.test`), пароль всех аккаунтов стенда — `correct horse battery staple`. Владельцем
  делает не API, а флаг `isOwner` в `yargram.json`, поэтому для нового датасета его надо дописать
  в файл и перезапустить стенд (иначе админ-маршруты ответят `403 NOT_ADMIN`).
- **Ждать документ, а не время.** После `Page.navigate` опрашивать
  `location.origin === BASE && document.readyState === 'complete' && Boolean(document.getElementById('root'))`.
  Иначе обращение к `localStorage` на `about:blank` падает с
  `SecurityError: Access is denied for this document`.
- Ключи localStorage: `yargram.accessToken` (активный токен), `yargram.accounts` (список аккаунтов),
  `yargram.onboardingDone`, `yargram.theme` (`'dark'` / `'light'`). Тёмную тему снимать всегда,
  если экран использует цвета из CSS-переменных.
- Скриншот смотреть глазами и править вёрстку по нему. Считать задачу выполненной только после
  проверки картинки, а не после успешного выхода скрипта.
- **Текст сообщений — это шифротекст.** Хранилище стенда шифруется ключом `DB_ENCRYPTION_KEY`
  из `.env`. Если датасет писался другим ключом, сервер вернёт `yargram1:…` как обычную строку, и
  на скриншоте будет мусор вместо переписки. Лечение: скопировать `data/yargram.json` в `.bak`,
  обнулить `messages`, `drafts`, `scheduledMessages` и заново наполнить историю **через API** —
  новые записи зашифруются текущим ключом и прочитаются.
- **Замороженный/удалённый аккаунт в списке — заглушка**: у неё `username: null`. Искать такого
  пользователя по нику можно только после разморозки, иначе получите `undefined`; надёжнее брать
  `id` из ответа и работать по нему.
- **Перед первым обращением к `localStorage` нужен `openApp()`** — даже если это первая строка
  сценария. Иначе `SecurityError` на `about:blank`.
- **Поле «О себе» в окне профиля имеет `id="profile-bio"`.** Оно неконтролируемое: сценарий
  пишет в `.value` и шлёт `input`, потом жмёт кнопку рядом. **Админ-панель — теперь отдельное
  окно, а не вкладка в настройках:** пункт «Админ-панель» в главном меню (только у владельца),
  окно ищется как `section[aria-labelledby="admin-title"]`, а поле юзернейма цели — первый
  `input` внутри него; рядом кнопка «Показать состояние». Списки дня рождения — `#birthday-day`,
  `#birthday-month`, `#birthday-year` (в настройках) и `#sheet-birthday-*` (в карточке профиля).
- **Описание собеседника видно только в карточке профиля** (клик по шапке чата), в самой переписке
  его нет. Описание помеченного SCAM подменяется на чтении — в карточке будет предупреждение.
- **Стенд и `npm run build` одновременно не запускать.** Сборка съедает CPU, у тестов на
  `embedded-postgres` срываются таймауты хуков, и прогон падает «на ровном месте». Сначала сборка,
  потом тесты.
- **Сиды для групп отправляют массив, а не одиночный id.** Эндпоинт `POST /api/groups/:id/members`
  принимает `{ memberIds: [uuid] }` (или `userIds`). Запрос с `{ userId }` упадёт с
  `400 MEMBERS_REQUIRED`.
- **Поиск элементов по тексту в сайдбаре идёт через `includes`**, а не точное равенство:
  `<button>` строки беседы содержит «Поход в горы», дату «00:09» и аватар — `textContent.trim()`
  будет длиннее. По сусекам-аккаунтам, наоборот, можно сравнивать строго, чтобы случайно не
  сцапать соседний пункт меню.
